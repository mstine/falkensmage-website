## Measured on 2026-10-30 at dedeec6 (planning-time facts, do not re-derive)

**AT Protocol, from the bluesky-social/atproto source:**

- createSession takes `identifier`, `password`; returns `accessJwt`, `did`, `handle`. createRecord takes `repo`, `collection`, `rkey` (optional), `record`, `validate`, `swapCommit`; returns `uri`, `cid`. getRecord takes `repo`, `collection`, `rkey`, `cid`, and its one declared error is `RecordNotFound`.
- app.bsky.feed.post: record key type `tid`; required `text` and `createdAt`; `text` maxGraphemes 300, maxLength 3000 bytes. 300 code points is at most 1200 UTF-8 bytes, so the byte limit cannot bind.
- The PDS validates the rkey against the schema (`schema.keySchema.safeValidate`), so a client-supplied key must be real TID syntax: regex `[234567abcdefghij][234567abcdefghijklmnopqrstuvwxyz]{12}`, 64 bits, top bit 0, 53 bits of microseconds, 10 bits of clock id, base32-sortable. The record-key spec sets no timestamp requirement. A second createRecord on a used key cannot create a second record; it errors.
- Facet: `{index: {byteStart, byteEnd}, features: [...]}`. `#link` holds `uri`; `#tag` holds `tag` with no leading `#`, max 64 graphemes. Offsets are UTF-8 bytes.
- `packages/api/src/rich-text/detection.ts` is the reference detection. URLs: start of text, whitespace or `(` before `https?://\S+`, strip one trailing `[.,;:!?]`, then strip `)` if the URL has no `(`. Tags: start of text or whitespace before `#`, trailing punctuation stripped, must hold a non-digit, 64 or fewer.

**Mastodon:** the limit counts graphemes and each URL counts 23, so `len()` in code points never undercounts.

**GitHub Actions, from the docs:** "events triggered by the GITHUB_TOKEN will not create a new workflow run", except that "workflow_dispatch and repository_dispatch events always create workflow runs". The schedule "can be delayed during periods of high loads", runs on "the latest commit on the default branch", and "In a public repository, scheduled workflows are automatically disabled when no repository activity has occurred in 60 days." workflow_dispatch needs the workflow file on the default branch.

**Repo:** default workflow permissions are read. Recent `hugo.yml` runs take 1 to 7.5 minutes. PyYAML is present locally but not in CI, and `actionlint` is not installed.

**Baselines at dedeec6:** `test-send-webmentions.py` 36 OK, `test-send-fa-email.py` 6 OK. `grep -c u-syndication scripts/send-webmentions.py` is 0. `grep -c syndicate .github/workflows/hugo.yml` is 0. `test_old_essay_sends_nothing_and_fetches_nothing_but_the_feed` pins the request log to the essay feed alone, so it changes in Task 3.

## Decisions recorded by this plan

**Graphemes (D-05).** Python's stdlib has no grapheme segmentation. Count code points. A grapheme holds at least one code point, so `len()` can only overcount, which means a note we pass is never rejected and the 3000-byte limit cannot bind. The cost, accepted: an emoji-dense note near the limit is truncated a little early, and "fits" means fits by this measure. Cuts land on whitespace, so a cluster is only split when a single word exceeds the budget.

**Mastodon length.** Each URL counts as 23, per the platform's own rule, else a 510-character note with a long URL is cut when it fits. The limit is a constant, not read from the instance API.

**Deterministic rkey.** `h` is the first 8 bytes of sha256 of the note path, big-endian. Microseconds are `int(date.timestamp()) * 1_000_000 + h % 1_000_000`, the clock id is `(h >> 20) & 0x3FF`, and the value is `(micros << 10) | clock`, encoded as 13 base32-sortable characters. So two notes collide only if dated in the same second and then at 1 in 2^30. Checked in a scratch run: `/notes/2026-11-01-0900/` at 09:00 -05:00 gives `3mzaxt2cwok3b`, which fullmatches the TID regex. This is the real guarantee on Bluesky: a lost record cannot create a second post at any time. getRecord only adopts the URI of a post that already exists, createRecord runs only on a clean `RecordNotFound`, and any other answer posts nothing.

**Deploy trigger and wait.** `notes.yml` runs `gh workflow run hugo.yml` with GITHUB_TOKEN, `actions: write`. Then it waits on the outcome that matters, the note's page returning an h-entry, not on the other run's status: plan 02's `wait_live`. `notes.yml` is NOT in the `pages` concurrency group. It waits on a run that needs that group, so sharing it would deadlock until the timeout. It has its own group, `notes-syndication`, which serializes posting. A deploy is dispatched only when a pending note's page is not already live, so a Bluesky outage retried every 15 minutes never becomes a deploy every 15 minutes (D-03).

**No loop (D-04).** The state commit is pushed with GITHUB_TOKEN, which starts no run, and `notes.yml` has no `push` trigger. If the token ever became a PAT, the push would cost one deploy and stop, because `hugo.yml` writes nothing. No commit-message marker is needed. Because that push starts nothing, the `rebuild` job dispatches `hugo.yml` once after any recording run so u-syndication links appear within minutes, which also lets Bridgy match them. This is the one case with two deploys per note: one to publish, one to show the links.

**What a note-driven deploy does to the existing jobs.** A dispatch with no inputs leaves `send_email` false, so `SEND_EMAIL` is false and the `email` job mails no subscriber. `send-fa-email.py` then decides on the newest essay, not the note: older than 24 hours is `skip-old`, any non-deleted email with that subject is `skip-duplicate`, otherwise it creates a draft. So a note-driven deploy creates at most one Buttondown draft, only for an essay under 24 hours old with no email yet, and it never repeats. Most note deploys create nothing. **One interaction to surface, not fix here:** that draft counts as an existing email, so a later `send_email=true` dispatch for the same essay is `skip-duplicate` and sends nothing. This already exists today with a push or the nightly rebuild. Note-driven deploys widen it: an essay dated before its release dispatch, with a note deploy landing in the gap, gets a draft and then no send. `scripts/send-fa-email.py` does not change in this run. The SUMMARY must name this for Matt. The `webmentions` job re-runs against its sent-state, so repeats cost nothing.

**Outbound Webmentions (D-10): notes send.** The sender already has everything: `load_entry`, `external_targets`, `send_all` and the state file take any source URL. It costs one more feed read in `main`, and the job already runs after every deploy. One interaction to handle: u-syndication anchors sit inside the h-entry, so the sender must skip them. A syndicated copy is not a citation.

**Cron minutes `7,22,37,52`,** because the top of the hour is when GitHub's schedule is most delayed. Every 15 minutes, as D-03 says. A note lands roughly 7 to 25 minutes after its date.

**60-day limit.** GitHub disables a public repo's schedules after 60 days with no activity, which would silently stop syndication and the nightly rebuild. FA commits land far more often, so this gets a comment in `notes.yml` and a line in the SUMMARY, not a mechanism.
