## Decisions recorded by this plan

**The text that goes out is read from the live page.** The post step fetches the note's published page and reads its e-content. Hugo stays the only Markdown parser, which is DP-13 applied here: a second Markdown converter in Python would be a second, drifting opinion. The same fetch proves the page is live, so "live before posting" cannot be skipped. A `[text](url)` link becomes `text (url)`; a bare URL stays bare.

**Note format is strict, enforced by code.** Front matter is YAML between `---` lines, keys `date` (required, RFC 3339 with an explicit offset or `Z`) and `draft` (optional, `true` or `false`), nothing else. The filename stem fullmatches `[a-z0-9][a-z0-9-]*` and is not `index`. Leaf bundles are refused. So the script's date and URL cannot drift from Hugo's, without Hugo in a cron job that runs 96 times a day and usually does nothing. Anything else is a loud failure naming the file.

**At most once.** Each success is committed and pushed before the next post, because a runner's disk is not durable. The Idempotency-Key is the sha256 hex of `falkensmage.com:mastodon:` plus the note path, so a retry inside an hour returns the first status. It holds nothing time-based, and it does not use `SITE`, which tests patch.

**Stale checkout is the sharpest double-post trap.** `actions/checkout` defaults to `github.sha`, fixed when a run is created. A run that queued behind another would read old state and re-post. So `post` runs `git pull --rebase origin main` before reading state, and plan 03 also sets `ref: main` on every checkout.

**Residual risk, accepted and documented in the script:** a Mastodon post succeeds, every push retry fails, and the next run is more than an hour later, so the key has expired. Then that one note double-posts on Mastodon. It needs GitHub's git service to fail at that exact moment and the schedule to then stall for an hour, and the run has already gone red with the URL printed for hand-commit. Hardening it would need a write-ahead commit per post or scraping one's own timeline back into text; neither earns its place.

**State wipe guard.** A missing or malformed state file is a hard failure, never "nothing recorded yet", because empty state means post everything. A note dated more than 7 days ago (the sender's MAX_AGE) is never posted: it is logged, gets a `::warning`, and exits 0. That bounds the damage of a bad revert, and it makes a backdated note a deliberate publish-here-only. Missing secrets are red, unlike the Webmention pull: a due note silently not going out is the failure.

**Test guards (D-14).** Three independent layers, so an unpatched test fails closed. The socket guard catches every Python path to a real host, including a forgotten `MASTODON` patch. The base setUp clears the secrets, so a forgotten stub cannot hold a real credential. The sentinel `ROOT` and the `file://` assertion stop a test pushing to the real origin. Hugo and git run as subprocesses the socket guard cannot see: Hugo is covered by `[security.http]`, git by the `file://` origin.
