## Measured on 2026-10-30 at dedeec6 (planning-time facts, do not re-derive)

**Hugo 0.160.1, prototyped in a scratch site:**

- `buildFuture` defaults to false. A future note produces no page, and `hugo.yml` passes no flag that changes that, so D-02 needs no build change. `hugo --clock 2100-01-01T00:00:00Z` does build it, which gives tests a fixed clock.
- With `content/notes/_index.md` and no notes, Hugo builds /notes/index.html and /notes/index.xml, `site.GetPage "/notes"` is non-nil and `.RegularPages` has length 0. A section holding only future notes behaves the same, so the nav guard needs nothing extra.
- A page with no title has an empty `.Title`, so baseof's title element needs its own branch.
- `.Plain` keeps HTML entities, so a template prints `&amp;ldquo;`. `.Plain | htmlUnescape | plainify | truncate 60` then `printf "%s"` prints correctly escaped text. Without the `printf` cast, `truncate` returns safe HTML and a literal less-than goes through unescaped in the title.
- `--minify` writes unquoted attributes and shortens the ellipsis to `&mldr;`, so parse with `html.parser` and `convert_charrefs=True`, never grep.
- Goldmark linkifies a bare `https://...`, the typographer curls quotes, and `#tag` stays plain text inside a paragraph.
- Test isolation from real notes works: a `[[module.mounts]]` with `source = "content"`, `target = "content"`, `files = ["! notes/**"]`, plus a second mount of a temp directory on `content/notes`. Defining a mount drops the default for that target, so both are needed. The data mount pattern, the `[security.http] urls = ["^$"]` rule and `--config hugo.toml,TMP/mounts.toml` are as in `build_site` in tests/test-pull-webmentions.py.
- `hugo new content notes/x.md --contentDir TMP` with `archetypes/notes.md` holding `date: {{ .Date }}` writes a date with the local offset, for example `2026-10-30T16:25:49-05:00`.
- The default RSS template writes an empty title per item and uses `.Summary`, hence a custom template. `transform.XMLEscape .Content` absolutizes relative links in RSS output.

## Decisions recorded by this plan

**One partial for the h-entry.** The note page and the index call the same `notes/entry.html`, so the markup cannot drift. There is deliberately no entry-level p-name: that is what makes it a note to every microformats consumer, and Bridgy treats a named entry as an article.

**The u-syndication block and the state file land in plan 02.** They render a record the state protocol writes. Shipping them here would leave an untestable branch, and the state stays whole in one plan.

**Empty state.** /notes/ exists from day one with a heading, a lede and the line "Nothing here yet." The nav link, and the feed and `rel=feed` links in the head, stay out until a note is published. Nothing links to an empty room.

**`rel=feed`.** A note that fits goes out with no link to the site, so backfeed has to find the original through the site. `rel=feed` in the head points at the h-feed for that reason. It costs one line, and without it Bridgy cannot connect a whole-note post to its page.

**Mentions reuse the FA partial unchanged.** It is keyed on `.RelPermalink`, so it needs no edit, and renaming it would only churn run 2's tests.
